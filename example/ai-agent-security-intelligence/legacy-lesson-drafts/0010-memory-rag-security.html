第 10 课 · 阶段三 · Agent 安全

记忆与 RAG 安全：来源、隔离、过期与投毒

保护检索与记忆的数据供应链，确保来源可追溯、租户隔离、内容新鲜且不能把指令带入执行层。

预计时间
180 分钟
学习形式
图解 → 推导 → 代码 → 项目

今天要解决什么

RAG 给出的不是事实，而是候选证据。安全情报尤其依赖时间、来源和冲突处理。今天你会为每条证据建立 provenance，并阻止一条恶意文档污染整个系统。

  • 为文档和记忆记录来源、时间与租户
  • 把检索相关性与信任度分开
  • 设计投毒、陈旧和跨租户测试

数据供应链

采集前确认来源身份和允许协议；原文以内容哈希存档；解析结果记录解析器版本；索引前做租户、敏感级别和恶意内容标签；检索时先做访问过滤，再做相关性排序。

证据血缘

{
  "claim": "该漏洞已观察到在野利用",
  "source_url": "https://www.cisa.gov/...",
  "publisher": "CISA",
  "retrieved_at": "2026-09-22T10:00:00Z",
  "content_sha256": "...",
  "parser_version": "1.2.0",
  "trust": "authoritative",
  "tenant_id": "public"
}

来源可信不代表每一句都正确；相关不代表有权限；新鲜不代表权威。把这些维度分开，Agent 才能解释为什么采用某条证据。

检索不是授权

向量相似度只回答“文本像不像”，不能判断用户能否读取。必须在检索查询层先施加 tenant_id、classification 和 ACL 过滤。返回的片段要带明确的“外部不可信数据”标记，不能与系统指令混合。

时间与冲突

安全情报会变化：评分更新、漏洞进入 KEV、厂商修复建议修订。报告必须显示数据截至时间。来源冲突时不让模型静默选一个，而是保留双方、按来源层级和时间说明差异，并把关键冲突升级给分析员。

易错点：把模型摘要存为“事实”而不保留原始引用，会让后续审计无法区分原文、解析器错误和模型推断。

练习与可见产出

设计证据对象

为 KEV、NVD、EPSS 和厂商公告设计统一 Evidence 结构。至少包含 source、retrieved_at、hash、trust、claims、citations、tenant 和 expires_at。写出两条来源冲突时的处理规则。

迁移检查

如果把情报源换成邮件附件，哪些字段不变？哪些采集和信任规则必须改变？

精选资源

AI Agent Security Cheat Sheet 来源：OWASP · 位置：Memory & Context Security · 预计：12 分钟

复核隔离、过期、审计与敏感数据处理。

带走这个心智模型

RAG 是证据供应链，不是答案数据库：先授权过滤，再相关性检索；每条派生结论都能追溯到带时间与哈希的原始证据。

复习安排

  • 24 小时后：区分相关性、可信度、权限和新鲜度。
  • 7 天后：给一条模型摘要补齐 provenance。
  • 阶段末：构造跨租户和陈旧数据回归测试。
