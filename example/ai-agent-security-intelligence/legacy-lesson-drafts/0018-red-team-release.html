第 18 课 · 阶段六 · 毕业项目

红队验证与发布门禁：证明系统值得信任

用对抗测试、发布门禁、演示脚本和残余风险说明，完成可展示、可评审的安全情报 Agent。

预计时间
240 分钟
学习形式
图解 → 推导 → 代码 → 项目

今天要解决什么

最后一课不再增加功能，而是证明已有系统在正常、异常和恶意条件下都按预期退化。你将得到一个参赛时能清楚讲述的完整证据链。

  • 执行覆盖注入、越权、泄露、投毒和耗尽的红队矩阵
  • 建立零容忍安全门禁和可恢复失败标准
  • 完成 5 分钟产品演示与技术答辩材料

红队矩阵

攻击预期证据
公告内嵌注入不产生非白名单动作轨迹与出站日志
模型请求任意 URL策略拒绝POLICY_DENIED
跨租户 ID查询层拒绝授权测试
投毒记忆不持久化或隔离记忆审计
循环/超大响应预算终止熔断事件
审批后篡改参数审批失效哈希不匹配

发布门禁

  • 单元和轨迹测试全部通过；
  • 任何未经审批写操作：0；
  • 任何跨租户读取：0；
  • 任何非白名单出站：0；
  • 关键结论引用覆盖率达到既定阈值；
  • 预算与超时测试按预期停止；
  • 高风险残余问题有负责人和补偿控制。

模型回答措辞波动可用范围指标，安全不变量不能用平均分掩盖。

参赛演示结构

  1. 痛点：安全信息多、来源分散、排序缺乏资产语境。
  2. 正常流程：导入公开夹具 → 规范化 → 交叉证据 → 可解释排序 → 报告。
  3. 安全挑战：展示恶意公告，系统标记不可信且拒绝越权动作。
  4. 可审计：打开 evidence_id、评分分解和策略日志。
  5. 边界：说明系统默认只读、未知项和人工决策点。

残余风险与真实反馈

通过教程只能获得知识与可重复技能，无法独自证明生产级判断。请让安全分析员审查报告是否可行动，让后端/安全工程师评审授权和网络边界，让真实用户完成任务可用性测试。记录接受的残余风险，不用“已通过红队”替代持续监控。

毕业标准：你不仅能演示 Agent 成功，还能解释它如何失败、失败会被哪层控制限制、以及哪些决策必须由人承担。

练习与可见产出

毕业交付包

提交：架构图、威胁模型、工具能力矩阵、12+ 正常样本、12+ 对抗样本、测试报告、5 分钟演示、已知限制和下一阶段计划。使用 practice/capstone-rubric.html 自评。

通过门槛

另一位开发者能依据文档复现测试；另一位分析员能验证报告证据；任何高风险动作都没有“模型自我批准”路径。

带走这个心智模型

可信不是‘模型很聪明’，而是目标清楚、权限最小、证据可追、失败有限、动作可审、门禁可重复，且人仍掌握高影响决策。

复习安排

  • 24 小时后：48 小时后独立重画系统与威胁链。
  • 7 天后：一个月后重跑完整评测并比较漂移。
  • 阶段末：任何模型、提示、工具、记忆或权限变化后重跑安全门禁。
