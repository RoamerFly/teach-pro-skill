第 2 课 · 阶段一 · 通用原理

手写一个最小 Agent 运行时

不依赖任何 Agent 框架，亲手实现可测试、有预算、可停止的最小运行时。

预计时间
210 分钟
学习形式
图解 → 推导 → 代码 → 项目

今天要解决什么

框架会隐藏循环。先手写一次，你才能在框架行为异常时知道问题发生在模型、解析、工具还是状态。今天的小胜利是运行一个完全离线、确定性的 Agent 循环。

  • 定义模型适配器和动作协议
  • 实现工具分发、观察回填与停止条件
  • 用伪模型测试循环，而不消耗 API

先定义动作协议

运行时不能靠自然语言猜“模型是不是想调用工具”。让模型只返回两种结构：tool 表示提议调用，final 表示给出答案。动作协议越小，验证面越小。

from dataclasses import dataclass
from typing import Literal, Any

@dataclass(frozen=True)
class Decision:
    kind: Literal["tool", "final"]
    name: str | None = None
    arguments: dict[str, Any] | None = None
    answer: str | None = None

实现最小运行时

循环的核心不是“不断问模型”，而是每轮都执行同一组不变量检查。这里的 policy.authorize 必须在工具之外，因为工具不能相信调用者已经获得授权。

class AgentRuntime:
    def __init__(self, model, tools, policy, max_steps=6):
        self.model = model
        self.tools = tools
        self.policy = policy
        self.max_steps = max_steps

    def run(self, task: str) -> str:
        transcript = [{"role": "user", "content": task}]
        for step in range(self.max_steps):
            decision = self.model.decide(transcript)
            if decision.kind == "final":
                return decision.answer or ""
            if decision.kind != "tool" or decision.name not in self.tools:
                raise ValueError("invalid decision")
            args = decision.arguments or {}
            self.policy.authorize(decision.name, args)
            observation = self.tools[decision.name](**args)
            transcript.append({"role": "tool", "name": decision.name,
                               "content": observation})
        raise RuntimeError("step budget exceeded")

这个实现故意没有“自动重试一切”。失败应被分类：可恢复错误可以有限重试；权限拒绝、模式错误和预算耗尽必须停止或交给人。

用 ScriptedModel 测试

class ScriptedModel:
    def __init__(self, decisions):
        self.decisions = iter(decisions)
    def decide(self, transcript):
        return next(self.decisions)

model = ScriptedModel([
    Decision("tool", name="lookup_cve", arguments={"cve": "CVE-2099-0001"}),
    Decision("final", answer="已完成查询，并保留来源。"),
])

伪模型让你确定性地覆盖工具调用、拒绝、超预算等分支。模型质量测试和运行时正确性测试是两类问题：前者需要样本与统计，后者应尽量像普通软件一样可重复。

四种失控方式

  1. 没有步数上限：工具失败后反复重试，形成费用与可用性风险。
  2. 工具名动态反射：模型可调用未显式暴露的函数。
  3. 参数不校验：合法工具被恶意路径、URL 或超大输入滥用。
  4. 把异常原样回填：内部路径、密钥片段或堆栈进入模型上下文。
运行时不变量：每个动作都必须命中已注册工具、通过结构校验、通过授权、消耗预算并产生可审计结果。
