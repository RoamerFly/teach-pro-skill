第 17 课 · 阶段六 · 毕业项目

研判与报告：可解释评分、引用和不确定性

用透明、可审计的规则组合公共信号与资产语境，生成带引用和不确定性的研判报告。

预计时间
240 分钟
学习形式
图解 → 推导 → 代码 → 项目

今天要解决什么

一个排序分数不是事实。它是面向某个决策的规则输出。今天你会把评分公式、权重、证据与未知项全部公开，让分析员能挑战结论。

  • 设计可解释且不重复计权的评分因子
  • 把未知值与低风险区分
  • 生成逐句带引用、标注推断的报告

透明评分

示例教学公式不是行业标准：

priority = 4·KEV + 3·asset_match + 2·internet_exposed + 2·EPSS_band + 1·severity_band − mitigation_credit

每个因子必须有定义、来源、取值范围和权重理由。KEV 与 EPSS 都涉及利用风险，需避免在解释中假装它们完全独立。分数用于排序调查队列，不自动触发修复。

未知不是零

没有资产清单，不等于资产不受影响；查不到 EPSS，不等于利用概率为零。使用三值或显式 unknown，并输出“缺什么证据会改变结论”。这能把 Agent 从答案机器变成调查助手。

报告契约

  1. 范围与数据截至时间；
  2. 优先队列及每项评分分解；
  3. 关键事实及来源链接；
  4. 模型推断与置信度；
  5. 证据冲突与缺口；
  6. 建议的下一步验证，不直接宣称已修复。
{
  "cve": "CVE-2099-0001",
  "priority": 9,
  "factors": {"kev": 4, "asset_match": 3, "epss": 2},
  "evidence_ids": ["ev-kev-1", "ev-asset-7"],
  "unknowns": ["internet_exposure"],
  "recommendation": "Validate affected version with asset owner"
}

人在回路中的判断

真实智慧来自组织情境：停机窗口、关键业务、补丁兼容、补偿控制和情报敏感性。Agent 提供证据与可解释排序，分析员确认资产、权衡影响并决定行动。把分析员修改保存为反馈，但不能自动当成全局规则。

练习与可见产出

实现评分解释器

输入 Finding 和 AssetContext，输出分数、逐因子解释、未知项和 evidence_ids。为“高 CVSS 但无资产匹配”和“中等 CVSS 但 KEV + 外网暴露”写两个测试。

作品标准

最终报告中，读者不用相信模型就能重新计算分数并打开每条关键证据。

精选资源

Enterprise Tactics 来源：MITRE ATT&CK · 位置：当前 Enterprise tactics 列表 · 预计：15 分钟

学习 tactic 表示对手目标；映射时必须有证据，不能由关键词自动强配。

FIRST EPSS API 来源：FIRST · 位置：epss 与 percentile 字段 · 预计：10 分钟

在报告中保留评分日期，并避免把概率估计写成已利用事实。

带走这个心智模型

评分是透明决策规则，不是客观真理；未知必须显式保留；报告把来源事实、计算推断和分析建议分层呈现。

复习安排

  • 24 小时后：不用页面解释为何未知不能当零。
  • 7 天后：手工复算一条评分。
  • 阶段末：让另一位同学只凭报告验证一条结论。
