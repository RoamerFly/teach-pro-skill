第 15 课 · 阶段六 · 毕业项目

安全情报 Agent：领域模型与证据流水线

把安全情报 Agent 定义为证据流水线：公开源采集、规范化、关联、排序、解释与人工研判。

预计时间
180 分钟
学习形式
图解 → 推导 → 代码 → 项目

今天要解决什么

项目不是“让模型搜索安全新闻”，而是从可信、可追溯的数据构造可行动的研判。今天你会固定领域对象、来源职责和报告契约。

  • 区分 CVE、KEV、EPSS、CVSS 与 ATT&CK 的角色
  • 设计 Evidence、Finding、AssetContext 和 Report 对象
  • 明确模型可以推断什么、不能冒充什么

系统回答什么问题

面向分析员的核心问题是：“在给定资产范围和时间窗口内，哪些公开漏洞信号值得优先调查，证据是什么，哪些信息仍缺失？”它不自动扫描网络、不生成利用代码、不直接修改生产系统，也不把公共严重性等同于组织风险。

四类来源

来源提供的证据不能替代
NVD/CVE漏洞描述、参考、CVSS 等在野利用事实
CISA KEV已知在野利用目录你的资产是否受影响
FIRST EPSS近期被利用概率估计确定性事件证明
MITRE ATT&CK对手战术与技术知识某 CVE 的自动唯一映射

领域数据模型

Evidence 是来源事实；Finding 是对一个漏洞的规范化聚合；AssetContext 描述组织环境；PriorityDecision 保存评分因子和缺口；Report 只引用这些结构，不从空白自由发挥。

事实、推断与建议

  • 事实：来源明确声明、可以引用。
  • 推断：由多条事实计算或模型归纳，必须标明方法和置信度。
  • 建议：面向具体资产和风险偏好的行动，需要说明前提。
报告规则：任何关键句都标为 source fact、computed inference 或 analyst recommendation，避免模型语气把概率伪装成确定性。

练习与可见产出

定义毕业项目 v1

在一页设计稿中写明用户、输入、输出、四个数据对象、数据源、五个非目标和三条成功标准。再用 reference/cti-data-model.html 检查字段。

阶段门槛

能解释为何 KEV、EPSS、CVSS 和资产相关性不能互相替代；报告结论可回溯到 evidence_id。

精选资源

Known Exploited Vulnerabilities Catalog 来源：CISA · 位置：How to use the KEV Catalog · 预计：15 分钟

理解 KEV 是已知在野利用的权威输入之一，而不是完整风险评分。

GET /epss 来源：FIRST · 位置：Endpoint 与 Additional Parameters · 预计：12 分钟

理解 EPSS 字段与查询限制；完成标准是能按 CVE 查询并保留日期。

带走这个心智模型

安全情报 Agent 是一条证据链，不是安全新闻聊天机器人：来源事实 → 规范化发现 → 资产语境 → 可解释优先级 → 带引用报告。

复习安排

  • 24 小时后：解释 KEV、EPSS、CVSS、ATT&CK 的不同角色。
  • 7 天后：把一段强断言拆成事实、推断和建议。
  • 阶段末：随机选报告一句话并追溯到 evidence_id。
