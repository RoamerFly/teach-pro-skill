第 3 课 · 阶段一 · 通用原理

工具契约：让模型建议、让程序裁决

把工具设计为窄、强类型、可授权、可审计的能力，而不是给模型一把万能钥匙。

预计时间
180 分钟
学习形式
图解 → 推导 → 代码 → 项目

今天要解决什么

大多数严重 Agent 事故不需要模型“越狱”；只要一个正常的模型在错误上下文中调用了权限过大的工具，就足够产生后果。今天你会把一个危险的万能工具拆成安全契约。

  • 写出工具的输入、输出、权限和副作用契约
  • 在执行前做结构验证与策略授权
  • 区分幂等、可逆和不可逆动作

六字段工具契约

每个工具至少回答六个问题：它做什么、输入模式是什么、输出模式是什么、需要什么权限、是否有副作用、失败时返回什么。描述不是给模型看的广告，而是系统的可执行边界。

字段安全情报例子
名称fetch_cisa_kev
输入无，或固定分页参数
输出经过模式验证的漏洞列表
权限仅 GET；域名白名单；无凭据
副作用网络访问与缓存写入
失败超时、源格式变化、验证失败

按能力而不是 API 拆工具

http_request(method, url, body) 看似通用，却把 SSRF、数据外传和任意写请求都交给模型。更安全的接口是 fetch_kev_catalog()、lookup_epss(cve)、read_asset_tags(asset_id)。这些名称直接表达业务能力，参数空间也小得多。

校验和授权分层

import re

CVE = re.compile(r"^CVE-(1999|2\d{3})-\d{4,}$")

def validate_lookup(args: dict) -> str:
    if set(args) != {"cve"}:
        raise ValueError("unexpected fields")
    cve = args["cve"].upper()
    if not CVE.fullmatch(cve):
        raise ValueError("invalid CVE id")
    return cve

def authorize(ctx, tool_name: str):
    if tool_name not in ctx.allowed_tools:
        raise PermissionError("tool not allowed for this session")

Schema 校验解决“形状是否正确”，策略授权解决“这个用户、这个会话、在这个时间、针对这个资源是否能做”。模型不能充当授权器，因为它同时读取潜在恶意内容。

安全的错误语义

工具应返回稳定的错误码，例如 TIMEOUT、NOT_FOUND、POLICY_DENIED，以及对用户安全的说明。内部异常写入受控日志，但不要把堆栈、文件路径、请求头或密钥原样交给模型。对写操作还要有幂等键，避免模型重试造成重复发送。

易错点：“模型承诺不会调用危险参数”不是控制。真正的控制必须位于模型无法修改的执行路径上。

练习与可见产出

拆掉万能 HTTP 工具

假设原工具接受 method、url、headers、body。为安全情报 Agent 设计三个窄工具，并为每个工具写：允许域名、HTTP 方法、输入字段、最大响应、超时、是否缓存。

自评量规

优秀答案不会让模型直接传任意 URL；查询参数有格式和数量限制；工具输出还要经过模式验证。

带走这个心智模型

工具不是函数列表，而是能力边界。输入模式保证“像不像”，授权策略保证“该不该”，审计记录保证“发生过什么”。

复习安排

  • 24 小时后：说出校验与授权的差别。
  • 7 天后：检查一个常用 API 包装器是否暴露了多余自由度。
  • 阶段末：给毕业项目所有工具标注只读/写入、可逆/不可逆。
