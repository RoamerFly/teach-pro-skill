第 9 课 · 阶段三 · Agent 安全

工具安全：最小权限与策略执行点

在模型之外实现能力白名单、资源范围、网络出口和每次调用授权。

预计时间
210 分钟
学习形式
图解 → 推导 → 代码 → 项目

今天要解决什么

一个只读情报 Agent 不需要 shell、任意文件、任意 URL 或数据库写权限。今天你会把‘模型可以使用什么’降成最小、可证明的能力集合。

  • 使用 capability 而非角色描述授权
  • 限制工具、资源、参数、网络和时间
  • 让策略失败时默认拒绝

五层最小权限

  1. 工具级：只暴露任务需要的工具。
  2. 操作级：同一资源区分 read、create、update、delete。
  3. 资源级：限制租户、目录、数据表和具体对象。
  4. 参数级：限制域名、查询数量、时间范围和响应大小。
  5. 时间级：短期凭证、审批有效期和速率限制。

策略执行点

策略执行点（Policy Enforcement Point）位于工具调用之前，接收真实主体、会话、工具、参数和环境信息。策略决策不能由模型写入的字段决定，例如不能相信模型自己声明 user_is_admin=true。

ALLOWED = {
    "student": {"lookup_kev", "lookup_epss", "read_public_report"},
    "analyst": {"lookup_kev", "lookup_epss", "read_asset_tags"},
}

def authorize(ctx, tool, args):
    if tool not in ALLOWED.get(ctx.role, set()):
        raise PermissionError("POLICY_DENIED")
    if args.get("tenant_id") not in (None, ctx.tenant_id):
        raise PermissionError("CROSS_TENANT")

网络与 SSRF

允许模型传任意 URL 会把 Agent 变成 SSRF 与数据外传通道。使用固定端点或服务端映射的 source_id；解析 DNS 后阻止环回、链路本地和私有地址；限制重定向；再次验证最终地址；设置超时、最大响应和内容类型；禁用用户自定义请求头。

更小更好：lookup_epss(cve) 比 fetch_url(url) 更安全，也更容易测试。

权限不是模型置信度

“模型有 98% 把握”不等于用户授权。授权来自身份、组织策略、用户明确意图与当前资源。模型可以估计内容风险，但不能授予自己新能力。策略服务不可用、日志写入失败或审批记录过期时，高风险动作应 fail closed。

练习与可见产出

能力矩阵

为匿名访客、普通学生、校内安全分析员、管理员四类主体，设计对公开源查询、内部资产读取、报告保存、消息发送、数据删除的权限。再写出每个允许项的资源和参数范围。

检查

匿名和普通学生不应触达内部资产；发送与删除必须单独审批；任何角色都不需要任意 shell。

带走这个心智模型

最小权限不是少写几个工具描述，而是在工具、操作、资源、参数和时间五层收窄能力，并由模型外部策略执行点逐次裁决。

复习安排

  • 24 小时后：不看页面列出五层最小权限。
  • 7 天后：把一个通用工具拆成两个窄能力。
  • 阶段末：模拟策略服务故障，确认高风险路径默认拒绝。
