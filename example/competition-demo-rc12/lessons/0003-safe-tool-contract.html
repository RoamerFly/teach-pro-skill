第 3 课 · 安全工具调用契约

把模型的调用提议变成可检查的数据契约：解析、参数、授权与预算各自负责什么。

正式课

今天要解决什么

今天做成一件事：为一个情报查询工具写清输入契约，并解释为什么“JSON 能解析”不等于“可以执行”。读图和示范约 20 分钟，练习约 10–15 分钟，一手阅读约 10 分钟。

  • 区分解析、参数校验与授权检查。
  • 沿控制流说明合法与被拒绝提议的去向。
  • 为一个新工具写出三类测试：成功、参数不符、未授权。

从调用提议接到程序边界

第二课把工具调用放回了模型与应用的循环。现在展开其中的程序部分：一段文本怎样变成能安全处理的提议。无需先完成补充课；关于没有 Thought 的注入问题，可按需阅读第二课补充。

先把“调用”拆成四件事

模型写出 {"tool":"search_reports","arguments":{"component":"component-a","limit":2}}，看起来像一条调用命令。但对程序来说，它首先只是一段文本。要让它成为一次受控调用，需要依次处理：读懂格式、检查参数、判断授权、执行已注册的函数。

把它想成校园实验室的器材申请单：表格填对，不等于申请人有资格使用；有资格，也不等于可以超量领用。申请单中的“批准”二字更不能替代管理员的批准。对应到 Agent，模型负责提出申请，应用负责核验，工具负责具体操作。

契约是双方对输入、输出和失败方式的共同约定。在这个例子里，调用提议必须有 tool 和 arguments；参数只能指定一个演练组件、返回数量为 1–3。应用还能用当前用户权限和剩余次数拒绝一份格式正确的申请。

解析成功，只是第一道门

json.loads把 JSON 文本变成 Python 对象：对象通常变成字典，数组变成列表，布尔值变成 True/False。这一步解决“读得懂吗”，不解决“应该执行吗”。调用提议可以格式完全合法，却要求一个未注册工具、越界的数量或没有授权的操作。

提议能否解析本例处理
{"tool":"search_reports","arguments":{"component":"component-a","limit":2}}能还须检查当前权限、预算与字段
{"tool":"delete_all","arguments":{}}能未知工具，拒绝
{"tool":"search_reports","arguments":{"component":"component-a","limit":999}}能数量超出本例 1–3，拒绝
{"tool":"search_reports","arguments":{"component":"component-a","limit":true}}能布尔值不是本例要求的整数数量，拒绝

为什么特意检查布尔值？Python 中布尔类型与整数有继承关系，只用 isinstance(value, int)可能放过 True。本例用 type(value) is int表达精确类型要求。实际工程也可以使用成熟校验库，但应知道所选校验是否会自动转换类型。

格式还要考虑大小和歧义。Python 默认 JSON 解码允许部分扩展值，并对重复键保留最后一个值；本例用钩子拒绝非标准数字和重复键，限制提议长度。真实服务还需限制嵌套、输入总量、并发和处理时间，不能把一个小函数当成全部防护。

工具注册：名字不是可执行代码

模型知道某个工具的描述，不等于程序应该执行任意同名表达式。我们预先创建注册表 REGISTRY = {"search_reports": search_reports}，只从这张表找到已定义函数，不能把模型文本交给 eval、Shell 或任意动态导入。

“工具存在”和“这次可用”也是两件事：注册表可能包含多个工具，当前会话的 allowed_tools只允许其中一部分。权限来自应用的授权状态，不从网页、报告或模型附带的 approved=true字段读取。即使模型收到恶意指令并写出一个合规 JSON，程序仍应执行相同的权限检查。

工具返回的结果重新进入模型上下文后，也不获得新的指令权限。最小权限能减少可发生的动作，但不能单独保证摘要准确或完全消除提示注入。内容可信度、结果核验与执行权限应分别处理。

完整示范：一个离线工具调度器

以下 Python 3.11+ 示例只调用本地合成函数，不接大模型、不访问网络、不读写报告文件。先读代码并预测输出；需要运行时，将代码保存为 tool-contract.py，执行 python tool-contract.py。不运行也能完成本课的纸面练习。

"""Offline teaching example: one tool, synthetic data, no model/network/filesystem calls."""
import json

def search_reports(component, limit):
    return [{"id": "SYNTH-001", "component": component, "source": "synthetic"}][:limit]

REGISTRY = {"search_reports": search_reports}

def reject_constant(value):
    raise ValueError("non-standard number")

def unique_pairs(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError("duplicate key")
        result[key] = value
    return result

def dispatch(raw, allowed_tools, remaining_calls):
    # Simple, bounded input for a one-level teaching protocol.
    if not isinstance(raw, str) or len(raw) > 4096:
        return {"ok": False, "reason": "input_size"}
    try:
        proposal = json.loads(raw, parse_constant=reject_constant, object_pairs_hook=unique_pairs)
    except (ValueError, RecursionError):
        return {"ok": False, "reason": "parse"}
    if type(proposal) is not dict or set(proposal) != {"tool", "arguments"}:
        return {"ok": False, "reason": "shape"}
    tool, args = proposal["tool"], proposal["arguments"]
    if type(tool) is not str or tool not in REGISTRY:
        return {"ok": False, "reason": "unknown_tool"}
    if tool not in allowed_tools:
        return {"ok": False, "reason": "permission"}
    if type(remaining_calls) is not int or remaining_calls <= 0:
        return {"ok": False, "reason": "budget"}
    if type(args) is not dict or set(args) != {"component", "limit"}:
        return {"ok": False, "reason": "arguments"}
    if args["component"] != "component-a" or type(args["limit"]) is not int or not 1 <= args["limit"] <= 3:
        return {"ok": False, "reason": "arguments"}
    # Only this line executes the pre-registered synthetic function.
    result = REGISTRY[tool](args["component"], args["limit"])
    return {"ok": True, "data": result, "remaining_calls": remaining_calls - 1}

if __name__ == "__main__":
    valid = '{"tool":"search_reports","arguments":{"component":"component-a","limit":2}}'
    print(dispatch(valid, {"search_reports"}, 1))
    print(dispatch(valid, set(), 1))
    print(dispatch(valid, {"search_reports"}, 0))
    print(dispatch(valid.replace('"limit":2', '"limit":true'), {"search_reports"}, 1))

从下往上看调用入口，再回到 dispatch顺着各个返回条件走：输入不合格就返回拒绝；只有最后的注册表调用才产生工具动作。参数检查在权限检查之前或之后可以按工程需求调整，但都必须发生在需要保护的动作之前。

四次示范分别得到：成功并剩余零次；权限拒绝；预算拒绝；参数拒绝。成功返回的 remaining_calls需要由调用方持久化或传给下一轮，不能每次重新传 1。并发生产应用还需原子预留预算，本例演示顺序单次调用，不包含并发控制。

观察输出时区分两层：这是实际运行 Python 得到的结果；其中报告编号与内容仍然是合成数据，不是实际查询 CVE 的结果。本例的四类拒绝也不是所有工具通用的错误清单。

从提议走到可核对的结果

  1. 收到文本提议，先限制长度，再解析为对象；不解释或执行其中的代码。
  2. 核对顶层字段和工具名称。注册表只包含开发者预先实现的工具。
  3. 核对当前权限和剩余次数，再检查参数结构、精确类型和业务范围。
  4. 通过后执行工具，记录实际返回；拒绝时记录阶段和原因，不编造成功 Observation。
  5. 调用方更新预算。后续是否重试、暂停或结束，由应用策略决定；不能用无限重试绕过拒绝。

现在改变一个条件：提议和参数都没变，但当前会话没有查询权限。仍然拒绝。这说明“格式正确”与“可执行”不是等价关系；如果你的测试只覆盖 JSON 格式，就遗漏了真正的授权边界。

教学后即时练习

格式正确后，还要查什么？

工具已注册，参数已通过校验，但当前会话没有该工具权限。程序应怎样处理？

JSON 布尔值能当数量吗？

本课契约要求 limit 是 1–3 的整数，模型提议 limit=true。按示例如何处理？

为新工具写契约与测试

工具 list_advisories(component, limit)只查询已授权组件，数量允许 1–5。写一份合法提议、一个参数不符的提议和一个格式合法但未授权的情形，指出各在哪一层被拒绝，并说明是否执行。

对照检查标准

合法样例必须同时满足字段、精确类型、范围、当前权限和预算。参数不符可用 limit=true 或 6；未授权应改变会话权限而不是改变合法参数。拒绝不产生工具动作。答案属于教学后应用，不据一次完成认定长期掌握。

带走这个心智模型

模型提议是数据；程序解析并按契约校验，再用当前授权与预算判断是否执行。注册表限制可调用函数，工具返回实际结果。格式、权限、成功验证是不同问题。
