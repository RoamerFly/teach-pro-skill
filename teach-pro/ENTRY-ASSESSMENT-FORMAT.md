# ENTRY-ASSESSMENT.md Format

入门评估用于定位起点，不是制造挫败感。题量应尽可能少，但足以判断先修能力和最近发展区。

```md
# Entry Assessment: {主题}

## Assessment purpose
{本次要判断哪些前置能力，以及为什么。}

## Evidence sources
- 用户自述：
- 简短问答：
- 示例任务或作品：
- 现有文件/成绩/项目：

## Findings
### Confirmed strengths
- {能力 + 证据}

### Partial knowledge
- {能力 + 能做到什么 + 卡在哪里}

### Missing prerequisites
- {已展示的缺口及证据；只有选择线索时写待核查与暂定教学安排}

### Misconceptions
- {具体错误模型}

## Starting level
{用描述性语言说明起点，不仅写初级/中级/高级。}

## Immediate teaching implication
- 第一阶段应从：
- 暂时跳过：
- 需要优先补救：

## Confidence
- 可直接核对的事实：{字段与原始选择；事实可核对不代表能力高置信}
- 暂定解释与教学安排：{依据与替代解释}
- 尚需后续验证：{需要什么解释、实作或迁移证据}
```

## 规则

- 不使用大量超纲题来“测水平”。
- 用户已经提供足够证据时，不重复测试。
- 对身体、创作、语言等能力，可用作品、录像、自述和现实反馈，但明确证据边界。
- 逐项区分观察、解释与教学决策：保留原始文件路径、字段与实际选择；选对只先记识别线索，选错先记待核查问题。只有解释、变式或复核支持时，才写入 Confirmed strengths 或确立具体误区；不从行业背景或一次选择推断高置信掌握。占位/无关作答记为未有效回答，不推断该能力差。
- 可以根据待核查问题先安排一节低风险的基础课，并在课内收集更强证据；暂时少讲某个概念是教学安排，不代表永久认定已经掌握。
- “不会/没学过”是学员自述，不是占位文本，也不是实际能力测量；记录本题未提供具体产出，按需教学和复核，不扩展为整体能力不足。开放自述没有标准正确答案，不以缺少预期格式判错。

## 学习者网页评估

- 学习者页面固定为 `practice/entry-assessment.html`；上面的 `ENTRY-ASSESSMENT.md` 是 AI 内部状态，两者不可混淆或放在同一路径。
- 每道需要作答的题目后提供有明确 `<label>` 的输入框；开放解释、代码或疑问使用 `<textarea data-save-key="entry-...">`。选择题若会影响课程起点，须在整个 `data-quiz` 容器上加唯一的 `data-save-key`，各单选项有不同且稳定的 `value`，确保选中项也能保存、恢复、导出和同步；只添加测验按钮而不记录选项，不算完成入门评估。
- 使用共享 `assets/course.js` 在当前浏览器自动保存、重新打开时恢复；本地运行环境可用时再由 `assets/sync.js` 自动写入课程工作区。提供清空本页与可选备份导出、可读的同步状态。学习记录不得提交到仓库或发送到远程服务。
- 参考标准默认折叠，题面先于答案；自述可作为起点信息，但不能直接判定已掌握。评估题若可在提交前查看解析或即时反馈，其答案只能作为可能受提示影响的起点线索，不标为严格无提示诊断；需要可靠基线时先收原始作答，再展示反馈。
- 页面须明示：AI 不能读取浏览器私有存储；但能在下一次对话中读取已经自动同步到当前本地工作区的记录。直接打开 HTML 或同步失败时，才需要学员上传备份或粘贴答案。
- 学员未提交答案时，将评估结果标为待验证，不臆测表现；可继续已生成的第一课，再根据真实证据调整后续课程。
- 首页和内部文档的题型数量从实际作答结构核对，不分别凭记忆填写；简单的一题一保存容器结构可用 scripts/check_course.py 检查，复杂多字段题还须人工核对。
