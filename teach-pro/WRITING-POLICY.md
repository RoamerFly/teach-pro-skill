# 教学文字：直接讲清楚

课程正文、标题、图注、练习、反馈、资源导学和课内答疑共同采用以下表达方式。学习者每读完一段，应更清楚一个概念、一个原因或一个可执行的步骤。

## 从知识和问题开始

- 标题直接命名要理解的对象、机制或任务，例如“在线识别需要哪些输入”“同一连接的窗口如何划分”。
- 解释按“对象 → 条件 → 机制 → 结果 → 例子”展开，顺序随问题调整。先回答学员正在问的事，再补必要的条件。
- 用肯定句说明结论成立时有什么、怎样工作、接下来怎样做。说明能力时写出所需输入、操作和检查结果。
- 需要比较时，分别讲清两种情况各自的过程与结果。让例子承担辨析作用，减少连续的警告、纠偏口号和预设指责。
- 条件紧挨对应结论，用普通陈述融入讲解；影响当前任务的例外才单独展开。

## 把判断写成可理解的条件

| 原表达 | 教学表达 |
| --- | --- |
| 为什么不能声称早期在线识别 | 在线识别的输入与时间条件 |
| 不能仅凭前30包就声称系统支持早期识别 | 早期识别要求全部输入在决策时刻已经可用。这里序列使用前30个载荷包，统计分支还使用完整流摘要；检验前30包识别时，应将统计特征也限制到这一时刻，并测量端到端延迟。 |
| 不能把五个人的结果推广到全校 | 这组数字描述五位同学当天的消费。估计全校情况时，下一步需要设计覆盖目标人群的抽样。 |
| 不要把替换和新增混为一谈 | 分别计算“替换一条”和“新增一条”：先写人数，再定位排序后的中间值。 |
| 不能说已经掌握，还没有足够证据 | 这次计算正确。接下来换一组数据，看你怎样解释选择依据。 |

表中的改写保留了科学条件和判断依据，并把它们连接到学习者能够理解、检查或执行的步骤。

## 让练习像老师在提问

题干正面说清对象和任务：“这条记录放在哪一组？依据是什么？”“预测改变条件后的结果。”“哪些输入在第30包到达时可用？”

反馈先指出本次答案中的具体进展，再解释需要调整的那一步，最后给一个可尝试的动作。例如：“总额150元算对了。平均数还需要除以人数5；请补上这一行，并写出单位。”记录本次表现、提示情况和后续复核条件，能力判断由内部学习记录维护。

## 让资源和页面服务学习

资源区讲“看哪里、能帮助理解什么、做什么练习”，选材过程记入内部资源库。选定资源需要登录或特定环境时，就近给一句实际使用说明和可用路径。

首页呈现当前课程、已经收到的作答和下一步；正文把主要空间用于知识讲解与练习。生成过程、版本修补、核验清单和能力置信度的详细推导放在内部记录。

## 正常使用否定和安全说明

否定可以用于定义、逻辑、实际错误反馈和必要操作约束，例如“分母为零时除法无定义”“该密钥认证失败，请检查配置”。准确性由具体对象、成立条件、例子与依据保证；去防御化并非宣称任意结论都成立。

权限、隐私、执行范围、来源核验和学习证据规则继续有效。面向学习者时，将相关规则转成当前操作所需的简短说明；安全课程也按概念、机制、案例和实践展开。

## 交付前通读

检查标题、开场、图注、反馈和总结：它们是否直接帮助理解；条件是否贴近结论；疑问是否得到正面回答；反复出现的否定能否改成具体做法。用一遍自然朗读复核语气，再对照原论证确认条件、公式、正确答案和执行规则完整保留。
