# HTML Course Output Specification

## 1. 目标

所有学习者可见的正式教程必须是可直接打开的 HTML 网页。课程应在不安装框架、不运行构建命令的情况下可阅读。

Markdown 仅用于 AI 内部状态。不得把 `DAILY-LESSON-FORMAT.md` 之类的模板直接当教程交付。

## 2. 页面类型

### `index.html`

课程入口，展示使命、路线、当前课、最近学习证据和下一步的教学依据。`{{PROGRESS_LABEL}}` 与 `{{PROGRESS_NOTE}}` 使用可核实的状态描述；没有预定义且可复算的分母时，不显示掌握百分比或伪精确进度条。

`{{REVIEW_AND_NEXT_HTML}}` 应以简短列表呈现已验证能力、待验证或具体误区，并说明下一课为什么推进、补救或先诊断。区分学员自述、原始作答、AI 判断与运行结果；引用可供 AI 追溯的课节和记录位置。尚无作答时显示诚实的空状态与下一行动，不把“已打开课程”写成掌握。

### `lessons/*.html`

单节完整课程，是主要教学单元。

每个课程页只承载一节课。页尾必须包含本课掌握证据入口、疑难与下节课问题的多行输入框、本地保存状态、清空和导出按钮，并说明下一节课会依据本课证据动态决定。

### `settings.html`（启用课内 AI 时）

课程统一设置页，集中管理模型提供商、API 地址、模型列表获取与下拉选择、会话 Key、输出上限、连接测试和忘记密钥。Key 默认遮蔽，只有主动点小眼睛才临时明文显示；无法获取列表时可手填模型 ID。所有课共用配置，各课聊天独立；课程页不放配置表单。可从 `assets/course-settings.html` 复制到课程根目录。

提供服务类型 kind 下拉框：OpenAI-compatible、OpenAI、DeepSeek、Ollama、自定义。非自定义选项自动填充默认 base_url，并显示对应协议参数说明；自定义不改写地址。预设来自服务端统一定义，切换不自动保存或发请求，具体规范见 LOCAL-TUTOR-SPEC.md。

### `reference/*.html`

压缩后的速查资料，适合复习，不替代第一次教学。适用时增加 `reference/resource-learning-center.html`，按阶段组织已核验阅读/视频及候选资源；不包含提前生成的未来课正文。

### `practice/*.html`

独立练习、阶段测验或作品评审页面，仅在确有必要时创建。

入门评估页属于特殊持久输入页面，固定为 `practice/entry-assessment.html`，不得放在课程根目录；这与模板相对路径及本地服务的页面白名单一致。它必须支持逐题输入、本地保存、恢复、清空和导出 JSON；学习者也可手动复制答案到对话中。

## 3. 技术要求

每页必须包含：

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>...</title>
  <meta name="description" content="...">
  <link rel="stylesheet" href=".../assets/style.css">
</head>
```

页面底部加载本地 `course.js`。所有内部链接使用相对路径。

**复用优先。** 生成新页面前先检查当前课程 `assets/`；已有样式、测验组件、脚本或辅助组件能满足需求时直接复用。未来课程可能重复使用的新功能应提取到 `assets/`，而不是重复内联。

## 4. 布局

### 桌面端

- 左侧使用能容纳导航文字的紧凑侧栏，左上角提供可键盘操作的折叠/展开按钮；折叠只隐藏导航，不删除入口或学习状态。无 JavaScript 时保留展开导航。
- 正文充分使用侧栏以外的可用宽度；长段文字单独限制行长，图、表、对照可占更宽空间，避免整页因固定窄容器产生大片左右空白。
- 可选右侧辅助区，但不能挤压正文。
- 正文行长适中，避免一行过宽。
- 默认采用紧凑但不拥挤的信息密度：标题、Hero、卡片和段落间距不应占用过多首屏；桌面首屏通常应同时看到课程标题、简介和至少一个正文区块。

### 移动端

- 左侧导航变为抽屉或顶部按钮。
- 代码块、表格、公式可在局部横向滚动，但页面本身不得溢出。
- 触控目标尺寸充足。
- 不使用依赖 hover 才能发现的核心信息。

## 5. 左侧导航

启用课内 AI 时，把页面模板中的 `{{SETTINGS_NAV_IF_ENABLED}}` 替换成导航最上方的“课程设置”入口（先于品牌块及页内目录），根目录页面指向 `./settings.html`，子目录页面指向 `../settings.html`；设置页标记当前状态。未启用时替换为空字符串，且不生成设置页与 Tutor 资产，不能留下死链。课页模板的 `{{TUTOR_SCRIPT_IF_ENABLED}}` 启用时替换为 `<script src="../assets/tutor.js"></script>`，否则替换为空字符串；最终 HTML 不得残留条件占位符。

必须包含可折叠区域：

1. 当前页面导航：H2/H3 锚点。
2. 相关文件：本课直接使用的参考页或练习页。
3. 课程导航：首页和全部课程。

当前页和当前章节应有视觉高亮，并有非颜色提示，如 `aria-current`。

## 6. 课程页组件

推荐使用以下语义化组件：

- `.lesson-hero`：标题、阶段、进度、时间。
- `.learning-objectives`：本课目标。
- `.callout.note`：补充说明。
- `.callout.key`：核心知识。
- `.callout.warning`：易错点或风险认知。
- `.example-card`：完整示例。
- `.exercise-card`：练习。
- `.resource-card`：精确资源。
- `.mental-model`：总结。
- `.lesson-pager`：上一课/下一课。

组件是视觉工具，不应把正文切碎成大量小卡片。普通说明优先使用段落、轻量分隔或短左侧强调线；只有交互、警告、状态或确需并列时才采用明显卡片。长解释保持连续阅读体验。

默认卡片使用克制的内边距与圆角；不要通过超大标题、大片留白、重复包裹或每段一卡来制造视觉层级。只有需要边界、交互、状态或重点提示的内容才使用卡片。

视觉节奏应与教学用途一致：课程首页用简短目标区、阶段路线与下一步行动建立方向；单课页用章节标题、系统图、正文解释、辨析题与产出任务交替组织，避免连续同形卡片。复杂概念优先使用可读的本地 HTML/CSS 图解，并紧跟文字说明；不得为了美化牺牲首屏信息密度或移动端可读性。新课程应复用共享 `style.css` 的配色、层级、交互状态和深色主题，确有新组件才扩展样式。

### 课程级视觉方向与灵活版式

课程创建时根据学科语义、教学任务、图解形式和学员偏好选择一个视觉方向，写入 `COURSE.md` 并应用到所有页面根元素的 `data-visual-theme`。模板默认 `studio`；共享 CSS 还提供 `systems`（结构与系统）、`reading`（文本细读）、`field`（关系与观察）作为可选起点。这些是组合语言而非学科硬映射：不得仅匹配关键词、按课随机切换，或让配色替代有内容的图解。主题除色板外可改变克制的 CSS 绘制纹理、Hero 装饰和局部组件轮廓；背景花纹不承载教学信息、不干扰正文，深色、窄屏与打印仍须可读。允许学员要求换风格。`data-theme` 的浅色、深色、跟随系统控制保持独立。

教学主体可按实际内容使用 `.content-pair`（图解与解释并列）、`.compare-grid`（双列对照）、`.reading-focus`（长文细读）、`.process-steps`（步骤过程）；窄屏会改为单列。仅在有助于理解时使用，长推理仍可连续排版。不同课可以改变组合与节奏，导航、学习记录、资源导学和答疑边界不随版式漂移。

按钮按操作角色统一：主操作（测验提交、保存/发送）、次操作（获取模型、导航）、危险操作（清空、忘记 Key）、图标操作（显示密钥）具有一致的尺寸、边框、颜色和 hover/focus/disabled 反馈；不可只靠颜色说明操作后果。复用现有类名与 `data-*` 行为，确需新按钮时使用 `.button--primary`、`.button--secondary`、`.button--danger`。每种视觉方向均需核对设置页、评估页和课页的按钮，不只检查首页。

## 7. 标题与锚点

- 每页只有一个 H1。
- 主节使用 H2，子节使用 H3。
- 每个学习者可见标题有稳定、可读、唯一的 `id`。
- 目录顺序与正文一致。
- 不使用随机哈希作为锚点。

## 8. 代码与命令

- 使用 `<pre><code>`。
- 标注语言和用途。
- 提供复制按钮。
- 紧邻代码解释关键行、输入、输出和失败模式。
- 不使用仅靠颜色区分的语法高亮。
- 若外部高亮库不可用，纯文本仍应清晰。

## 9. 数学公式

优先策略：

1. 简单公式使用可读 HTML 或 MathML。
2. 复杂公式可使用 MathJax/KaTeX，但应明确网络依赖或将库放在本地。
3. 公式后解释每个符号、单位和适用条件。
4. 移动端公式容器可局部滚动。

不得只放公式不解释。

## 10. 图表与图片

- 能用语义化 HTML/CSS/SVG 表达时优先本地表达。
- 对流程、架构、信任边界等有视觉结构的内容，优先制作原创、与当前任务一致的图解；不为每段文字强行配图，也不让图替代机制解释。
- 图片使用课程内相对路径、准确 `alt`、`<figure>` 和说明性 `<figcaption>`；复杂图在邻近正文解释阅读顺序、箭头或边界的含义。适合时使用 SVG 以保证缩放清晰。
- 图中文字、线条和背景应在手机端、深色主题与打印时仍可辨认；过宽的架构图可在图框内左右滑动，并给出可见提示，不得让整页横向溢出。SVG 中有关键文字时，`alt` 或正文需提供等价信息。
- 不使用无授权或来源不明的图片。
- 从外部资料提取图片前核验许可与归属，保留来源、作者和必要的授权说明；许可不明时自己重画事实关系，不复制原图的视觉表达。
- 外部图表工具不可用时，页面仍有文字替代说明。

## 11. 视频和外部资源

默认使用资源卡链接，不强制嵌入 iframe。嵌入可能受跨域、登录或网络限制。

当过程、动作或时序值得直接演示时，可在相关章节加入本地 `<video controls playsinline preload="metadata" poster="...">`，提供可实际播放的 MP4、中文 WebVTT 字幕轨和文字讲解/逐字要点；默认不自动播放，学习者可静音、暂停或仅阅读正文。视频应短而聚焦，并压缩到合理大小；不要把同一段无增益地重复成大量文字、图片和视频。没有视频时不要生成空播放器或占位资源。

视频文件、字幕和海报使用课程内相对路径，并在直接打开 HTML 和本地服务两种方式下验证播放。部分浏览器会阻止 `file://` 页面加载旁边的 WebVTT 字幕；若要求双击即能看懂，应把简洁字幕烧录进自制视频，同时保留可选字幕轨和邻近文字稿。本地服务模式还要验证字幕轨实际加载。第三方嵌入仅在许可、隐私和网络依赖都适合时使用，同时提供无需嵌入也能学习的替代路径。不要下载、截取或重打包许可不明的外部视频。

资源卡至少显示：

- 标题和来源
- 文档章节 / 视频 P 数 / 时间段
- 推荐理由
- 预计时长
- 学习完成标准
- 导学角色、优先/选读与访问限制；无法观看/阅读时的替代路径

课程中的“本课一手阅读与视频”先展示少量优先项，其余用原生 `<details>` 折叠；不要每个字段再包一层卡片。视频给出看前预测、暂停观察与看后产出，学习结果复用页尾 `data-save-key` 输入框。资源中心同样使用现有导航、主题与紧凑样式，并区分当前资源和未来候选。

外链使用：

```html
<a href="..." target="_blank" rel="noopener noreferrer">...</a>
```

## 12. 习题

### 折叠答案

使用原生 `<details>` 和 `<summary>`，即使 JavaScript 失效也能使用。

折叠容器本身负责展开正文的左右内边距，不仅靠子段落 margin 留白，避免组件的 margin 简写覆盖后使文本贴边。检查文字稿、答案、选读与嵌套列表展开后的布局；标题、正文与代码块保持一致的视觉内沿，移动端不得横向溢出。

### 选择题

可使用 `data-*` 配合 `course.js`：

- 提交后显示正确答案和原因。
- 错误选择显示对应误区。
- 默认允许重新选择。
- 不永久锁定第一次选择，除非明确是考试模式。
- 同题各选项在可见长度、句式完整度和信息密度上必须等价；自然可行时保持相同词数并缩小字符数差异。不得让正确答案因更长、更具体、更完整或格式独特而暴露，也不得为了机械等长牺牲语言自然性。

现有 `course.js` 会在每个 `[data-quiz]` **内部**查找 `[data-quiz-submit]` 与 `[data-quiz-feedback]`；按钮或反馈区若成为兄弟节点，点击不会绑定。最小结构如下，实际选项仍须按上面的教学要求设计：

```html
<div data-quiz data-save-key="entry-q1" data-correct-answer="正确选项的简短说明">
  <label><input type="radio" name="q1" value="a" data-correct="true" data-feedback="原因">选项 A</label>
  <label><input type="radio" name="q1" value="b" data-feedback="误区">选项 B</label>
  <button type="button" data-quiz-submit>检查回答</button>
  <div data-quiz-feedback aria-live="polite"></div>
</div>
```

若选择结果会影响后续教学决策，`data-save-key` 应标在整个 `data-quiz` 容器上，各选项使用唯一且稳定的 `value`；共享保存、导出与同步脚本将记录该值。没有这两个条件的选择题仅用于即时自测，不可声称 AI 已取得该题作答。需要无提示入门诊断时，先保存原始作答再揭示反馈；同页可预先展开的解析无法证明作答前未被看过。

交付前至少实际触发一次选择和提交，确认正确、错误反馈以及重新选择后的更新；仅有按钮、属性或静态 HTML 完整性不代表交互可用。

### 开放题

提供检查清单、示例标准或量规，不伪装自动评分。

若开放题答案会改变后续教学决策，应使用带 `data-save-key` 的文本框本地保存；AI 只有在答案同步到可访问的课程工作区，或用户主动提交后，才能把它作为后续课程证据。

### 本地学习记录组件

共享 `course.js` 应提供无外部依赖的行为：`data-save-key` 文本框自动保存并恢复；`data-save-clear` 清空当前页面记录；`data-save-export` 导出当前页面记录；`data-save-status` 显示保存状态。导出内容至少包含课程/页面标识、保存时间和字段内容，不得伪造掌握结论。

本地工作区可用时，同时加载 `sync.js`，只向课程启动器的同源本地服务写入页面答案；显示独立的同步状态。同步成功后，备份导出是可选操作，不应作为学员每课必做步骤。具体见 [LOCAL-SYNC-SPEC.md](./LOCAL-SYNC-SPEC.md)。

### 可选课内答疑组件

启用时复用 `tutor.js`，在学习记录附近提供当前模型、课程设置入口、发送说明/确认、上下文预览、问题输入、对话恢复与保存状态，不提供模型配置控件。统一设置页加载 `tutor-settings.js`，密钥字段使用 password、保存后清空，不接入通用 data-save-key 自动保存。长上下文折叠，聊天区域局部滚动，不能遮挡课程；模型回答用安全文本渲染。配置变化后须重新确认发送范围。静态模式显示启动提示，不假称答疑或文件同步可用。详见 [LOCAL-TUTOR-SPEC.md](./LOCAL-TUTOR-SPEC.md)。

## 13. 可访问性

- 正确使用 `header/nav/main/section/footer`。
- 导航有 `aria-label`。
- 抽屉按钮有 `aria-expanded` 和 `aria-controls`。
- 表单控件与 `<label>` 关联。
- 键盘可完成导航、折叠、复制和测验操作。
- 文字与背景对比度足够。
- 动画遵守 `prefers-reduced-motion`。
- 颜色不是唯一状态信号。

## 14. 主题与打印

- 支持浅色、深色和跟随系统。
- 将主题选择存储在本地浏览器。
- 打印时隐藏导航、按钮和交互控件。
- 打印正文应保持标题、示例、答案和资源链接可读。

## 15. 离线与依赖

- 默认阅读体验只依赖本地 `style.css`、`course.js` 和可选的 `sync.js`。
- 课程核心内容必须离线可读。
- 外部文档和视频链接在线时才可访问，但不影响课程主体。
- 不得要求用户安装 Node、Python 或启动本地服务器才能阅读；自动同步到 AI 可访问的课程目录则需要本地运行环境或等效受控通道。

## 16. 增量写作与文件完整性

当一个逻辑文件无法一次完整写入时：

- 分多次追加或继续写入同一个目标文件，直到内容完成。
- 不因单次写入限制人为拆成多个 `part-*` 文件。
- 每次续写都检查衔接点，防止重复、遗漏、HTML 标签失配、列表/编号断裂。
- 完成后从文件级别检查开头、结尾、关键章节和导航是否完整。

交付前检查：


- 所有开始标签有合理闭合。
- 页面不存在未替换的双花括号占位符。
