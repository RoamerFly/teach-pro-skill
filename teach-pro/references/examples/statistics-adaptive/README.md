# 校园消费统计 · 自适应教学案例

这是一套面向专家阅读与宿主演练的完整案例：同一学习目标和第一课，两份不同作答，对应不同的教学支持。它与[最小示例](../statistics/README.md)分工不同；最小示例验证基础组件，本案例展示讲解质量、证据判断和正式课／补充课的配合。

## 一键查看

在 Skill 根目录运行，输出目录必须尚不存在：

```sh
python scripts/build_adaptive_example.py <新的输出目录>
```

打开输出目录的 `index.html`，依次查看共同起点、案例 A、案例 B。每个分支是独立可移动的课程工作区，可用各自启动器真实填写与保存；总入口是展示页，不是待续课的课程目录。按需只构建一个分支可用 `--case a` 或 `--case b`。

构建器组装预写的教学案例，不调用模型、不分析现场作答、不自动续课。所有示例输入和预期判断来自 [cases.json](cases.json)，不是 TeleAgent 新生成结果。三个快照代表不同教学时点／可能结果，不是一次请求批量生成多节课的示范；实际 Skill 仍按[逐课交付规则](../../../LESSON-DELIVERY-POLICY.md)执行。

## 展示顺序

1. **一句话请求 → 简短访谈。** “我想学习统计学”先问用途和基础；得到每周两小时、先图后算的回答后规划，不臆测学生会编程。
2. **评估 → 第一课。** 用一道选择题与一道解释题定位起点。合成评估回答支持暂从均值与中位数开始；不把选对当长期掌握。
3. **第一课 → 两种作答。** 首课从消费场景讲两种中心，拆解奇偶样本、替换和新增的边界，提供可保存的解释题与重新作答的辨析题。
4. **读取文件 → 有范围的判断。** 各分支 `synthetic-inputs/0001-answer.json` 保存明确标注的模拟输入；`learning-records/0001-answer-review.md` 展示预期解读。正式体验者的输入仍只由服务写入 `learner-submissions/`，不混用两类文件。
5. **调整支持 → 主线向前。** 两个分支都推进“比较分散程度”；A 减少填表提示、增加迁移，B 同轮提供首课补充页并增加新课计算支架。不用补充页代替下一正式课，不宣称补充页已纠错成功。

| 分支 | 原始表现 | 能采用的判断 | 本轮交付 |
| --- | --- | --- | --- |
| A | 区分替换和新增，说明中间位置 | 本题解释正确；保持与迁移待验证 | 第 2 课：点图、平均绝对偏差与变式任务 |
| B | 原值计算正确，但认为中位数遇高值总是不变 | 当次回答过度概括；稳定性待核查 | 第 1 课补充：换例复核；第 2 课：相同新目标、更多计算支架 |

每个工作区的 `reference/decision-trace.html` 将原始回答、题目条件、判断边界、交付依据和候选下一步放在一起。首页、画像、路线与学习记录沿用同一判断范围，新课均标为待作答。

## 内容与资源

- [首课正文](first-lesson.html)：原创图解、完整计算、边界与解释任务。
- [第二课正文](second-lesson.html)：共同新目标；不同支架与练习由案例配置注入。
- [补充页正文](supplement.html)：按排序位置换一种表示，并用新数据复核。
- [资源核验与逐课任务](resources.json)：具体教材章节与发布者视频页，记录核验程度、学习预算和替代路径。只给链接，不下载或复制外部图文／视频。
- [构建器](../../../scripts/build_adaptive_example.py)复用最小示例的部署和共享模板，不维护第二套 Runtime。

## 在宿主中验证真正的自适应生成

导入当前 Skill，在新的独立课程目录发送 cases.json 中的初始请求，回答访谈并完成评估，再请求第一课。获得真实首课后，根据实际题面构造两种有差异的合成回答；通过该课程页面保存，在两份隔离课程副本中分别请求下一课。不要直接把本案例的字段写入题面不同的课程，也不要改动真实学员记录。

核对：教学 AI 是否读取正确课节文件；A／B 的支持是否与作答一致；B 是否同时交付补充与新正式课；正式课是否以新知识为主体；交付、作答、能力状态是否分开。保留提示、原始输入与产物，才可报告实际宿主行为。编写好的案例页面与浏览器检查不替代这一验证。
