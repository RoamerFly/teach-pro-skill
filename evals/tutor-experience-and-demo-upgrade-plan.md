# 课内答疑体验与参赛演示升级计划

制定日期：2026-10-01。队伍：重邮FFBond。作品：学途智伴——大学生长期自适应学习智能体。

状态：计划待执行。源码基线为 `f615f11`，Skill 为 1.1.0-rc.3。本次先提交计划，不修改 Runtime、课程、视频或说明文档。

## 目标与范围

让学员读课时保持清爽，需要讨论时一键进入大尺寸聊天窗口；回答排版完整，多轮交流与本地记录连续。演示旁白以自然讲解为目标，以真人试听决定是否采用，而不是凭音量指标判定。

逐课教学协议、学习证据判断和课程目录体系保持稳定。本次更新聚焦 Tutor Runtime、共享页面资产及比赛材料；配音工具只属于材料制作流程，不进入 Skill 的课程运行依赖。所有工作串行进行，阶段验收后单独提交并推送 main。

## 现状与证据

1. `teach-pro/assets/tutor_chat.py` 的 `model_request()` 仅读取字符串 `choices[0].message.content`，空正文统一提示“接口未返回兼容的文本回答”；未区分 finish_reason、思考预算耗尽与异常响应结构。上一轮在 1024 token 下出现失败，调整现有配置到 4096 后成功；未取得失败响应的 finish_reason，预算耗尽仍是推断。
2. [DeepSeek 官方接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)标明思考默认启用，正文和 reasoning_content 分开返回，length 表示生成受到长度限制。修复应识别返回状态与调整请求参数，而非仅放大上限或把思考文本当作最终回答。
3. 多轮对话已经存在：服务端按课保存全部原文，向模型带入最近成功消息与当前课正文；当前窗口为最近 10 条消息及 16000 字符预算。需要改善的是界面、呈现与窗口完整性，不另建重复聊天系统。
4. `tutor.js` 使用 textContent 显示全部回答，因此 Markdown 的井号、星号、代码围栏直接可见。当前纯文本路径避免 HTML 执行，但未完成富文本排版。
5. 当前课页插入完整聊天面板、长确认框、上下文预览与说明。用户要求删除前两种操作负担及预览区，改为按钮和大弹窗；后端和规范中的 consent 要一起调整，不能只隐藏 DOM 或默认代勾。
6. 当前 edge-tts 只提供有限的语速、音高、音量控制。[项目说明](https://github.com/rany2/edge-tts#custom-ssml)明确不支持自定义表现型 SSML。进一步自然化需要口播稿、句子韵律和引擎选择共同处理。

## 目标界面

课页仅保留一个与课程主题一致的“问 AI”按钮；可放在课页工具栏并在窄屏提供固定入口，不同时堆多个重复入口。保留 `#lesson-tutor` 作为兼容定位点；从设置页返回答疑时可直接打开弹窗。

```text
┌──────────────────────────────────────────────────────────────┐
│ 本课答疑 · 第 1 课             DeepSeek Flash       ⋯     ×  │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│                     当前课的连续对话                         │
│              用户问题 → 排版后的 AI 回答 → 追问               │
│                                                              │
│              新回答到达 / 查看历史 / 请求状态                 │
├──────────────────────────────────────────────────────────────┤
│ 可选：已引用的课文片段                                  移除 │
│ 输入问题…                                                    │
│ 基于本课 · 自动保存                         引用选文    发送  │
└──────────────────────────────────────────────────────────────┘
```

- 桌面窗口初定宽度 90–94vw、上限约 1440px，高度 88–92dvh；中等屏幕跟随可用空间，手机近全屏。以 1440×900、1280×720 和 390px 窄屏实测后定稿。
- 页头和输入区固定在弹窗内，对话区独立滚动；默认聚焦输入框，Esc/关闭按钮退出并把焦点还给入口。关闭弹窗保留本课聊天、草稿和课程滚动位置。
- 对话正文初定 16px、行高 1.6–1.75，随窄屏调整；用户消息可用轻背景，AI 回答以连续文档流排版，不把每个段落套成卡片。代码、引用和表格按内容需要区分，按钮与图标沿用共享样式。
- 使用原生 dialog/showModal 或等效可访问实现；[浏览器原生行为](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog)可提供模态层及背景交互隔离。点击遮罩不直接丢弃正在编辑的草稿。
- 模型与连接状态简短展示；备份、清空聊天、课程设置放入更多菜单。清空保留一次确认，避免误删记录。
- 删除课页发送勾选框和“查看将发送的本课上下文”区域；设置页也删除重复同意勾选。点击获取模型、保存、测试或发送就是对应操作的明确触发，打开页面和弹窗只恢复本地状态。
- 设置页主流程为选提供商 → 填 Key → 获取并选择模型 → 保存；测试为可选动作。Key 继续默认遮蔽，小眼睛主动显示。地址、预算和思考模式等高级参数可折叠，主要操作不被长说明挤占。
- 页面只保留当前模型、基于本课、自动保存等必要状态；技术细节进入规范或更多菜单。界面简化不改变同源凭证、密钥处理、课节隔离和请求预算等后台实现。

## 串行实施阶段

### 1. 修复响应处理与 DeepSeek 答疑预设

**文件：** `teach-pro/assets/tutor_chat.py`、`course-settings.html`、`tutor-settings.js`，配套 Python 测试。

- 将请求构造、响应正文提取和错误分类分开。记录有限的非敏感诊断：提供商/模型、HTTP 状态、finish_reason、正文长度、是否有思考字段、token 用量和用时；不记录思考原文、完整错误体或认证信息。
- DeepSeek 普通课内答疑默认采用非思考模式，在确认该模型支持后显式发送 `thinking: {type: disabled}`；思考模式放入高级设置。普通答疑与连接测试分别设预算，不把其他提供商强行套入 DeepSeek 参数。
- 更新适合当前模式的输出默认值，兼容旧配置；确需思考时提供合理预算。不要把永久提高 token 上限当作唯一修复。
- 区分正文为空且长度耗尽、正文部分完成、正常结束却空正文、格式不支持、429、认证错误和超时。部分正文明确标为未完成，不写成 complete；收到 reasoning_content 但没有正文时不冒充最终答案。
- 对 finish_reason、部分结果和重试关联采用兼容字段或经校验的新状态，同步历史读取与课程生成 AI 的判断；旧 schema 和 complete/pending/failed 记录保持可读，不能因新增状态导致旧聊天拒绝恢复。
- 错误给出短、具体且可操作的结果，例如“回答达到长度上限，可调整输出预算后重试”；格式错误在可展开详情中保留安全诊断。
- 重试由学员点击发起，关联原失败消息，避免重复插入问题。首版保持整段响应与准确加载状态，流式响应独立评估。

**验收：** 模拟 stop+正常正文、length+空正文、length+部分正文、只有思考、空 choices、异常 JSON、429、超时等情况；每类有正确状态和本地记录。新密钥准备后，用 Flash 做一次连接和至少三轮真实问答，核对参数与响应状态。未取得真实失败证据前不宣布预算耗尽为唯一根因。

### 2. 实现 Markdown 回答排版

**文件：** 新增共享回答渲染模块及本地依赖资产；调整 `tutor.js`、`style.css`、模板资产引用与检查脚本。

- 支持段落、标题、加粗、列表、引用、行内代码、代码块和表格；代码块可复制，表格与长代码只在自身区域横向滚动。标题等级与字号适配对话，不能把回答里的一级标题渲染成课程大标题。
- 采用成熟 Markdown 解析器与 HTML 清理器的本地固定版本，如 Marked + DOMPurify，检查包体、许可证并保留许可文件；课程不依赖 CDN，也不增加学员的 Node/npm 安装步骤。
- 按允许标签和 URL 协议渲染，去掉脚本、事件属性及危险链接。默认不自动加载远端图片；模型生成的原生 HTML 不直接执行。[Marked 项目说明](https://github.com/markedjs/marked)明确解析器本身不负责清理输出。
- 本地聊天文件继续保存原始 Markdown，不保存替换后的正文；渲染与原文分离，代码里的 `#`、`*` 和围栏内容不被误删。用户消息保留朴素文本显示。
- 公式是否加入专门渲染，在常用语法验收后再决定；长表格与代码的阅读体验优先。

**验收：** 混合中文与 Markdown 样例、代码中的井号、嵌套列表、长代码、表格、未闭合围栏均可读；脚本、onerror、javascript URL 不执行。离线阅读和聊天历史恢复不依赖外网。

### 3. 大弹窗聊天与流程简化

**文件：** `tutor.js`、`style.css`、`course-settings.html`、`tutor-settings.js`、后端对应操作检查及浏览器测试。

- 用入口按钮与大弹窗替代正文聊天面板，所有颜色、边框、按钮、输入框沿用当前课程 CSS 变量；浅色、深色及不同课程主题均一致。
- 移除前述长勾选框、上下文预览、默认大段提示及相应控件状态。同步修改服务端 consent 检查和配置变化处理；旧客户端的遗留字段可兼容接收，但不要求新客户端伪造同意字段。
- 保存模型即启用当前课程连接。弹窗打开时恢复当前课历史、模型和服务状态；未配置时给一个简洁的设置入口。切回课程或发送前刷新配置，发生变化时更新模型标签，不要求重复勾选。
- 多轮聊天按完整回合组织近期上下文，避免预算截断后只剩孤立回答；保留每课原始文件与状态兼容。模型记忆来自实际带入的窗口，不宣称无限记忆。
- Enter 发送、Shift+Enter 换行，输入框自动增高；处理中避免重复提交。滚动历史时不强制拉到底，提供新回答定位；请求失败保留问题和重试入口。
- 关闭弹窗不会取消已发出的服务请求或丢失结果；重新打开可恢复。长操作反馈放在消息附近，复制、备份、清空放在低干扰位置。
- 引用正文前保存选中片段，打开弹窗后显示可移除的引用条，避免弹窗获取焦点后丢失选择。

**验收：** 入口只占少量正文空间；大窗、窄屏、深色和课程主题实测通过；键盘打开、关闭、焦点返回与中文输入法发送均正确。三轮交流、关窗重开、刷新、跨课切换和失败重试均不丢记录、不串课、不重复提问。清空只影响当前课。

**验收：** 单元测试与真实浏览器测试通过；skill-creator 校验、check_course 与 Demo 资产一致性检查通过。用“智鉴 Agent”做一次新生成组件检查和已有聊天恢复检查；静态打开仍可阅读、作答，核心教学行为关卡保持通过。

### 5. 配音样音与真人感定稿

**文件：** 参赛材料的讲稿、旁白制作脚本和音轨；不改变课程 Runtime。

- 先做同一段 20–30 秒样音，覆盖开场、提问、解释和过渡。目标语气是队员在向评委自然演示：开场有邀请感，提问有疑问语调，解释有重音，操作段有适当停顿。
- 口播稿按意思群写短句，术语发音提前约定；少用统一的“第一步/接着/这里/然后”播报句。录音按连贯段落完成，不把每一句割成独立音频，也不故意加入机械笑声或呼吸。
- 比较当前工具的最佳口播样音与一个真正支持说话风格的可用引擎。[Azure Speech 的表现型 SSML](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-synthesis-markup-voice)是一条候选路径，必须先核实具体中文声音支持的风格、可用账户和费用；未取得新服务授权前不开户或付费调用。
- 如果可用合成样音仍明显不自然，采用队员本人/授权讲解者的真人录音；给出分段稿与录音清单，再处理噪声、剪辑和字幕。不克隆他人音色。
- 由用户听短样音选择方向，再生成完整旁白；未通过样音不反复制作整片。试听重点为像自然解释、停顿连贯、术语正确、音色稳定；主观自然度和流畅度建议各达到 4/5 后继续。
- 完整音轨完成后重新安排停留、操作与回答展示时间，目标 165–175 秒，最终低于 180 秒；音量统一只是技术验收的一部分。

**需要用户时：** 收听短样音并选择；如采用新付费语音服务，确认服务与预算；如采用真人，提交队员本人或已获授权的干净录音。
