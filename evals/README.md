# Teach Pro 评测方案

评测目标是观察 Skill 是否按学习证据作出教学决策，而不是评价某个模型生成的文笔。以下案例使用**合成学员数据**；它们不能证明真实学习效果、长期保持或多学科泛化。每次运行须记录平台与版本、模型、输入副本、输出文件、检查结果和失败点，不预填通过率。

## 可重复的本地检查

从本仓库根目录运行：

```powershell
node --test tests/*.test.cjs
```

从 `example/ai-agent-security-intelligence/labs/secure_cti_agent` 运行：

```powershell
python -X utf8 -m unittest discover -s . -p test_runtime.py
```

前者检查导航、课程视觉主题和评估选择题的保存/恢复/同步脚本；后者检查**示例项目运行时**的只读工具、拒绝和预算，不等于 Skill 教学效果评测。Windows 以外可省略 `-X utf8`。浏览器、本地服务与不同 Agent 平台仍须另行实测。

## 教学行为案例

每案使用独立的示例课程副本。不要把夹具写入正式示例或真实学员工作区，也不要把预期答案提前交给被测 Agent。生成结果须检查实际 HTML、`COURSE.md`、`ROADMAP.md` 和学习记录，而不是只读模型自述。

| --- | --- | --- | --- |
| E01 初次建课 | 只有目标、基础自述和时间预算 | 先明确 Mission 与评估；只交付第一课；未把自述写成已掌握 | 本案未运行；用户要求先评估的变体见 E09 |
| E02 具体误区 | 使用 [`fixtures/0001-misconception.json`](./fixtures/0001-misconception.json) | 读取原始答案及疑问，指出“来源可信≠动作授权”；不直接推进工具契约，交付完整补救课 | 本案未运行；不以 Transformer 案替代 |
| E03 证据不足 | 仅有“看完了、继续”，没有有效作答 | 交付证据诊断课，不虚构通过 | 待验证 |

## TeleAgent 第二轮记录

检查日期：2026-09-29。产物由用户在 TeleAgent 中生成，当前生成模型、导入包指纹及这轮客户端版本未记录；不推断其与上一轮完全相同。保留原始工作区 `../../TeleAgentTest2/transformer-attention-mechanism/`，不把它作为发布示例或真实学习效果证据。

- `learner-submissions/entry-assessment.json`：四个字段均落盘，选择值为 `length-sum` 与 `linear-activation`，开放题为测试占位文本；证明保存，不证明能力。

- 未通过项：单次选择被写成“已掌握/已确认误区”；点积比较省略长度条件，公式正确未消除图注及注意力预告中的过度概括；资源导学与当前课资源记录缺失。
- 后续门槛：重新导入修订版，从原始答案复核并修订已有第一课，不新增第二课；比较能力判断、图注/公式/例题/总结/反馈的一致性、资源导学和内部记录。只更新文档不算行为通过。第一课后的诊断/推进测试须随后另做。
