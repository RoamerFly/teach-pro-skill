# Teach Pro 评测方案

评测目标是观察 Skill 是否按学习证据作出教学决策，而不是评价某个模型生成的文笔。以下案例使用**合成学员数据**；它们不能证明真实学习效果、长期保持或多学科泛化。每次运行须记录平台与版本、模型、输入副本、输出文件、检查结果和失败点，不预填通过率。

## 当前主线：智鉴 Agent

后续 TeleAgent 测试固定使用“智鉴 Agent：智能体开发与安全实战”，基础条件和目标沿用用户原始要求。按[主线复测计划](./teleagent-main-course.md)串行验证：先评估，再生成第一课，最后检查证据不足、误区补救和新证据后的动态续课。

仓库 `example/ai-agent-security-intelligence/` 是展示案例与比较参考，不是无缺陷的标准答案。行为结果以 TeleAgent 新生成产物为准；手工修订的页面不能替代生成行为验证。发现问题先追溯到可复用的 Skill 规则、模板或运行资源，再做最小修订与复测。

Transformer 第二、第三轮及 C01/C02/E11 保留为历史问题和补充探针，不作为当前下一步主线，也不要求继续重跑。测试学科的选择不改变 Teach Pro 的通用教学定位。参赛完善围绕教学质量、自适应闭环、易用性与可复核演示；这些是内部质量目标，不冒充赛事官方评分标准。

## 可重复的本地检查

从本仓库根目录运行：

```powershell
node --test tests/*.test.cjs
python -X utf8 -m unittest discover -s tests -p 'test_*.py'
python teach-pro/scripts/check_course.py <课程目录> --json
```

从 `example/ai-agent-security-intelligence/labs/secure_cti_agent` 运行：

```powershell
python -X utf8 -m unittest discover -s . -p test_runtime.py
```

仓库测试检查导航、课程主题、保存脚本、默认设置及只读检查工具；课程结构检查不访问外链，不读取答案、聊天或密钥，不判断概念正确性。示例项目测试检查运行时的只读工具、拒绝和预算。以上都不等于教学效果评测。Windows 以外可省略 `-X utf8`。浏览器、本地服务与不同 Agent 平台仍须另行实测。

已具备 Playwright 与浏览器时，可运行 `node tests/sidebar-theme.browser.cjs "课程目录" "截图目录"` 检查主题面板底部布局、长目录、键盘、主题恢复和窄屏。可用 `TEACH_PRO_BROWSER` 指定浏览器可执行路径。测试使用独立浏览器上下文与静态课程，不提交作答、不请求模型；这不是课程阅读所需依赖。

Test4 入门评估可运行 `node tests/assessment-ui.browser.cjs "课程目录" "截图目录"`。需要已有 Playwright、浏览器及 Python 3.11+；可用 `TEACH_PRO_PYTHON` 指定解释器。测试在临时副本检查选项/按钮样式、无样式类回退、反馈、七个字段同步、文件恢复和导出，不修改真实课程的作答。

2026-09-29 的实际修复与浏览器结果见[入门评估 UI 验证记录](./records/2026-09-29-test4-assessment.md)，包括截图和未验证边界。

随后开展的[主线 T01 内容复核](./records/2026-09-29-mainline-t01-review.md)记录了概念条件修订、原始答案保护及进入第一课前的用户操作；页面修订不计为新生成行为通过。

## 统一记录原则

每案记录 `通过 / 失败 / 未运行 / 条件受限`，并附精确证据文件；有部分通过时列出失败子项。首页掌握状态只能来自具体作答和条件，不能用随意百分比代替。演示中的模拟答案须在画面或说明中标明为模拟学员数据。
